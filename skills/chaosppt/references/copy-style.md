# PPT 文案风格：去除防御性小字

此约束默认用于内容规划、HTML 编写、改稿和导出前审阅。以受众要理解的结论、已有事实和证据组织页面。

## 页面准入

每句可见文字应承担明确作用：表达观点、解释证据、帮助阅读，或呈现用户要求的信息。Agent 的制作进度、自我免责和材料收集提醒留在制作记录中。

默认去除 Agent 自行附加的这类文案，包括其变体和英文表达：

- 制作占位：“待测”“待补充”“真实材料待补充”“图片待替换”“待用户确认”；TBD, TODO, pending data, placeholder。
- 预防性质疑：“未经充分验证”“真实效果待验证”“数据待核实”“尚需进一步测试”。
- 泛化免责：“仅供参考”“以实际为准”“不代表真实业务表现”“请谨慎解读”；for reference only, subject to verification。

按作用判断，而非对词语一律替换。“待测”出现在用户要求的测试进度表时，是业务状态；Agent 为产品介绍页额外加上的“性能待测”角标，属于制作或验证提醒。介绍防御性写作的引文也可以保留原句。

## 材料缺口的处理

1. 先确定当前证据实际支持的结论，使用准确的范围和措辞。
2. 缺少测试数据时，省去性能比较、空白表格和结果占位卡片，介绍已实现的能力、设计机制或已有验证。
3. 缺少图片时，选用有依据的文字结构、流程或图形；版面按实际内容重新组织。
4. 把补充材料请求、制作待办、非本页主题的测试清单写入 `deck.json` 的 `notes` 或交付说明，避免自动生成局限性页。
5. 若缺口影响受众的判断，直接收窄可见主张；用户要做验收、风险或决策分析时，把相关状态作为正文清楚呈现。

保持事实准确。没有耗时记录，就省去耗时指标；缺少播放验收，就描述“内嵌 MP4/GIF”，避免扩大为“所有 Office 平台播放通过”。从合成数据推导真实增长、把计划写成已实现、把未验证写成通过，都不符合这套文案约束。

## 典型改稿

| 场景 | 原稿 | 处理 |
| --- | --- | --- |
| 产品能力页 | 页脚“吞吐量待测、原生 Office 播放待验证” | 正文呈现已实现的排版、导出和嵌入能力；测试任务进入备注。 |
| 缺少业务材料 | 卡片“真实材料待补充” | 省去卡片，用现有材料重新分配页面空间。 |
| 缺少量化证据 | 大数字“XX%”，小字“数据待核实” | 省去数字和脚注，准确介绍已有机制或定性事实。 |
| 演示数据图 | 多个角标反复声明样例、非真实、仅供参考 | 在图题或图注保留一次简洁的“合成数据示例”；来源保留有用的出处信息。 |
| 测试进度页 | 用户材料中的“播放兼容性：待测” | 作为测试状态保留，结合该页的任务和验收口径呈现。 |
| 预算或预测页 | “预计投入 80 万元” | 保留“预计”及影响理解的计算口径，避免把预测写成实际值。 |

## 交付前审阅

- 检查正文之外的页脚、母版、图例、徽标旁小字、图片说明、SVG 文本和 Canvas 绘制文案。
- 对命中的词语判断语境：这是受众需要的信息，还是 Agent 为材料缺口追加的自我保护？
- 对后者直接删除或重组页面；字号变小、颜色变淡、换同义词、挪到可见角落都没有解决问题。
- 删除之后复核主张仍有证据支持，并保留用户明确要求的状态、数据口径和必要来源。

这是 Agent 的创作与审稿约束。渲染器不会按关键词自动删除用户提供的内容；`inspect` 的布局/资源检查也不代替文案审阅。
