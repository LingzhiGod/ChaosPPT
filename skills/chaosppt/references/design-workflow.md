# 主题先行：美学与设计流程推荐规范

## 目标与优先级

先建立整套 PPT 的设计系统，再设计页面。页面是统一主题的不同构图，不是各自独立的海报。

这是新建演示文稿的默认推荐流程，不是一套固定品牌风格。用户明确要求、已有品牌规范和指定模板优先。编辑既有 PPT 时继承已确认的设计系统，除非用户要求改版。无特殊要求时，由 Agent 根据内容和受众选定合理方案并执行，不为颜色/字号的每个选择反复请求确认。

## 流程顺序

### 1. 明确任务与信息结构

整理受众、使用场景、画布比例、演示距离、语言、品牌约束、素材和输出模式，形成内容大纲。此时决定每页的信息目标，但尚不铺开页面视觉设计。

### 2. 确定美学方向

用少量明确词语描述方向，例如“克制、清晰、专业”或“明快、亲和、轻量”，并落实为实际规则：

- 整体明度与视觉密度：浅色/深色、留白比例、信息密集程度
- 文字气质：字体类别、标题力度、正文可读性
- 几何语言：直角/圆角、边框粗细、装饰密度
- 图像与图标：摄影/插画/线性图形的统一处理方式
- 重点表达：主要依靠大小、位置、字重还是强调色

不要仅写“高级”“好看”“科技感”等无法指导页面制作的形容词。无需为了展示技术能力混用多种视觉风格。

### 3. 确定全稿配色与背景政策

先给颜色分配角色，再决定颜色值：

| 角色 | 开始页面设计前需要确定 |
| --- | --- |
| 页面背景 | 全稿默认背景色或背景处理方式 |
| 内容承载区 | 卡片/表格底色、边框、分隔线 |
| 标题与正文 | 各级标题、正文、次要文字、图注和页脚颜色 |
| 强调 | 主强调色、必要时的辅助强调色，以及使用范围 |
| 数据系列 | 系列色及固定映射，不逐页随机换色 |
| 语义状态 | 完成/进行中/计划、实际/目标/预测等角色的颜色与辅助标记 |

推荐默认统一底色。若采用背景变体，所有变体仍属于同一套配色方案，并在设计开始前声明“什么页面可以使用什么背景、对应什么文字颜色”。例如仅封面与章节页使用预定深色变体，其余内容页保持浅色；也可以全稿统一深色。没有明确用途就不切换，不把任意深浅交替当作默认美学。

色彩数量以支撑内容为准。优先一组中性色加有限强调色；分类较多的图表可以另有统一的数据调色板。不同标题级别可以使用同一颜色，但每个角色的映射必须明确。

### 4. 确定完整字体层级表

为每个角色填入具体的字体、字号、字重、行距和颜色。不要只写“标题大一些、正文小一些”，也不要把范围留给每页自行选择。

下面是 1600×900 画布的**示例起点，不是全项目固定数值**；根据品牌、材料、字体实际度量和展示场景调整后，采用一组确定值：

| 角色 | 示例字体角色 | 示例字号（CSS px） | 示例字重 | 示例行距 | 颜色角色 |
| --- | --- | ---: | ---: | ---: | --- |
| 封面标题 | 标题字体 | 80 | 700 | 1.2 | 标题主色 |
| 页面主标题 H1 | 标题字体 | 64 | 700 | 1.25 | 标题主色 |
| 二级标题 H2 | 标题字体 | 40 | 700 | 1.3 | 标题主色 |
| 三级标题 H3 / 卡片标题 | 标题字体 | 28 | 700 | 1.4 | 次级标题色 |
| 正文 | 正文字体 | 28 | 400 | 1.5 | 正文主色 |
| 图表/表格标签 | 正文字体 | 22 | 400 | 1.4 | 正文或次要文字色 |
| 图注/来源 | 正文字体 | 20 | 400 | 1.4 | 次要文字色 |
| 页码/页脚 | 正文字体 | 16 | 400 | 1.4 | 次要文字色 |

中英文、数字、代码需要不同字体时，分别声明用途和回退字体；不为每页另选字体。标题默认不加末尾句号，完整文案规则见 [copy-style.md](copy-style.md)。

同层级文字跨页保持同样的角色样式。遇到长标题或内容过多时，先改写、换行、重组或拆页；确有必要的“紧凑标题”等变体应在主题中明确命名、定义尺寸及使用条件，而不是逐页随手缩字号。可编辑输出需考虑接收端字体可用性；HTML 成功加载本地字体不代表 PPTX 已内嵌该字体。

### 5. 保存设计规格并实现共享主题

在项目根目录保存 `design-spec.md`，至少记录：

1. 受众、场景、画布与输出模式
2. 美学方向及其具体表现
3. 默认背景、完整色值表与预定变体适用范围（无变体时明确写“无”）
4. 字体层级表，包含各级标题的字体、字号、字重、行距与颜色
5. 安全边距、网格、间距阶梯、图片/图标风格、圆角/线条规则
6. 数据系列/状态色映射，以及代表页选择

将这些决定落实到共享 `theme.css` 和必要的母版。样式以角色命名，例如 `--title-color`、`--h1-size`、`.type-h1`、`.type-body`，页面控件引用这些角色。图表 JS 也读取同一组颜色变量，不另设随机调色板。

`design-spec.md` 是创作记录，不是幻灯片内容，也不是新的 manifest 配置。`deck.json` 仍只使用引擎支持的 `theme`、`fonts`、`masters` 等字段。共享主题与显式控件契约同时适用，不能以美学为由绕过原生控件的技术边界。

**开始页面设计的条件**：背景方案、配色表、字体层级及标题颜色已经有具体值，共享主题文件已经建立。未完成这些决定前，不批量制作页面。

### 6. 代表页验证，再展开全稿

先制作足以验证主题的代表页，例如封面、普通内容页和信息密集的数据页；短稿按实际需要减少，不强制固定数量。检查字体层级、可读性、颜色对比、留白、内容密度和输出效果。

之后使用同一主题批量制作其余页面。通过构图、分栏、图表形式、主次与留白获得变化，不随意更换字体、底色或标题颜色。修改主题时更新共享变量，并复查所有受影响页面，而不是叠加越来越多的逐页补丁。

### 7. 导出前做全稿一致性检查

逐页检查之外，还要查看全稿缩略图并对照设计规格：

- 背景一致，或严格遵守预定的统一配色/变体规则
- 各级标题的字体、字号、字重与颜色没有漂移
- 正文、数字、图表标签、图注和页脚使用既定字体角色
- 强调色、数据系列色与状态色含义一致
- 边距、网格、间距、圆角、线条和图像处理属于同一个系统
- 没有为了避免拥挤而临时缩小重要文字
- 显式控件、图片回退和媒体仍遵守技术契约
- 实际 PPTX 的字体与排版经过检查，而不只看浏览器预览

这些是 Agent 的设计与审阅规范，不是已经实现的自动主题校验器。`inspect`/`verify` 的结构与资源检查不能代替全稿美学审阅。
