# Control motion and shared transitions

**Goal:** One declarative control-motion contract compiles to browser playback and native PowerPoint effects, including groups, directional bar reveals and shared-object page transitions.

**Architecture:** Pure shared motion contract/timeline → browser runtime + player → resolved control IDs/native timing trees + Morph transitions → independent package verification. Static capture restores authored layout; animation is not baked into PDF/PNG. Invalid/conflicting declarations fail closed.

**Public contract:** data-pptx-motion JSON object/array (effect, direction, durationMs, delayMs, trigger, order); data-pptx-shared stable key; slide.transition {effect:none|fade|morph,durationMs}. Six effects: fade-in/out, fly-in/out, reveal-in/out. Direction semantics: fly starts/ends at the named slide edge; reveal/erase begins at the named side. Group is an atomic target; overlapping ancestor/descendant motion and media targets are rejected initially.

Acceptance distinguishes semantic correspondence from pixel-identical rendering or actual PowerPoint/WPS playback certification. Morph requires a viewer with Morph support; old viewers receive an explicit Fade fallback. Browser group/shared behavior uses the same IDs, timing and timeline, not arbitrary CSS animations.
